# 数据契约

本文件定义三张表的字段、含义与单位。第二步的代码严格按此实现，两人不得单方面改动字段名。

## 1. `data/params_assets.csv`

储备资产的参数表。一行代表一类资产。

| 字段 | 类型 | 含义 | 单位 |
|---|---|---|---|
| `asset_id` | string | 资产代码，与 `portfolios.csv` 对应 | — |
| `asset_name_cn` | string | 中文名称 | — |
| `same_day_ratio` | float | 正常情形下当日可变现的比例（对应 LCR 的流动性折算系数） | 0–1 |
| `settle_days` | int | 变现并完成结算所需天数 | 天 |
| `stress_haircut` | float | 压力情形下的额外扣减，默认 0 | 0–1 |
| `annual_yield` | float | 年化收益率 | 小数，如 0.04 表示 4% |
| `source` | string | 参数来源：「团队假设」或具体出处 | — |
| `note` | string | 备注 | — |

有效可动用比例 = `same_day_ratio - stress_haircut`。

## 2. `data/portfolios.csv`

组合配置表。一行代表「某个组合持有某类资产的权重」。

| 字段 | 类型 | 含义 | 单位 |
|---|---|---|---|
| `portfolio_id` | string | 组合代码，A / B / C | — |
| `portfolio_name` | string | 组合名称 | — |
| `asset_id` | string | 资产代码 | — |
| `weight` | float | 该资产在组合中的权重 | 0–1 |

同一 `portfolio_id` 的 `weight` 之和应为 1。

## 3. 结果表 `outputs/results.csv`（第二步生成）

一行代表「某组合 × 某冲击率 × 某规则」的一次结果。

| 字段 | 类型 | 含义 | 单位 |
|---|---|---|---|
| `portfolio_id` | string | 组合代码 | — |
| `shock_rate` | float | 赎回冲击率，占流通量的比例 | 0–1 |
| `rule` | string | 兑付规则，`fcfs` 或 `pro_rata` | — |
| `same_day_available` | float | 该组合当日可用金额 | 与流通量同单位 |
| `coverage_ratio` | float | 兑付覆盖率 = 当日可用 ÷ 赎回请求 | — |
| `gap` | float | 流动性缺口，覆盖率不足时的差额 | 与流通量同单位 |
| `failure_flag` | int | 1 表示覆盖率低于 100%，0 表示足额 | — |
| `portfolio_yield` | float | 组合年化收益率 | 小数 |

## 与 Basel III LCR 的对应关系

| 本项目 | Basel III LCR |
|---|---|
| `same_day_ratio` | HQLA 的流动性折算系数（haircut 的补数） |
| `same_day_available` | 折算后的 HQLA 金额 |
| `coverage_ratio` | LCR 分子 ÷ 分母 |
| 期限为 1 个工作日 | 期限为 30 天 |
| 主体为持牌稳定币发行人 | 主体为银行 |

两者结构同构，但期限与主体不同，因此本项目称为「日内流动性覆盖率」，不直接自称 LCR。
